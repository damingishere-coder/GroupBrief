# FTS5 本地性能记录

2026-09-14，Windows 11 10.0.26200，Python 3.12.10，SQLite 3.49.1，
AMD64 Family 25 Model 33 Stepping 0。合成消息，不使用生产聊天或 AI。

命令：`python scripts/benchmark_knowledge_search.py --counts 200000 1000000`。
每词运行 12 次，P95 按 nearest rank 取样本最大值，包含数据库连接、原文验证和摘要生成。
这是一轮本机实验，不是生产 SLA。

| 消息量 | 索引时间 | 数据库大小 | 手机 P95 | Claude Code P95 | 显示器 P95 | 不存在 P95 |
|---|---:|---:|---:|---:|---:|---:|
| 200,000 | 15.59s | 190,631,936 B | 24.71ms | 23.70ms | 27.73ms | 1.93ms |
| 1,000,000 | 81.70s | 958,746,624 B | 113.09ms | 128.15ms | 130.66ms | 2.21ms |

上述四种查询均无超时。前三种词命中约 10% 的合成消息。

“项目”命中约 90% 消息：20 万条下 P95 为 150.61ms；百万条下 12 次均超过
450ms SQLite 查询预算而返回受控超时，观察到的 P95 超时返回时间为 456.55ms。
后者不是成功检索延迟，不能计作通过。界面建议增加群、日期或更具体的关键词。

优化前使用相关度与 ID 的联合排序；改为 FTS5 内置 rank 排序后，避免候选结果的额外全量排序。
同分结果分页由固定索引版本与查询游标约束，并有跨连接、321 条同分记录的分页回归测试。
20 万条普通搜索 P95 不超过 500ms 的首版目标通过；百万条极宽泛查询仍有上述边界。
