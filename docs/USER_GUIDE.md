# GroupBrief 2.0 使用指南

## 第一次使用

1. 打开本机的 `http://127.0.0.1:8766`，进入 **设置 → 系统健康** 和 **启动检查**。确认数据库可用，再检查你需要的微信读取、模型与发送能力。
2. 进入 **群聊管理**，添加并绑定群聊，先测试读取。没有真实微信环境时可使用结构化 JSON 导出数据。
3. 保持该群的微信发送关闭，选一个有消息的日期，生成第一份群报。AI 调用需要你自己的模型服务与登录配置。
4. 回到 **今日工作台**，点击群报卡片，在右侧查看排行榜、图片和提示词。
5. 检查群名、日期、数字和图片内容，再决定是否发送。开启发送前须完成当前微信客户端与桌面环境的实际测试。

## 新导航怎么用

| 入口 | 日常用途 |
| --- | --- |
| 今日工作台 | 选择运行日期，查看多群进度与待处理项，打开右侧日报工作区 |
| 日报作品 | 集中查看日报；从“浏览画廊”、图片风格和排行榜模板入口管理作品 |
| 群聊管理 | 搜索、绑定群，配置调度、图片与发送，停启用和查看回收站 |
| 运行任务 | 查看各阶段状态、日志、任务详情与历史恢复 |
| 消息归档 | 查询原始消息，查看历史归档与回收站 |
| 设置 | 运行设置、系统健康、启动检查、恢复信息 |

旧书签仍保留兼容入口。新版以电脑多群处理为主要场景。

## 处理一份日报

在工作台打开日报后，群列表保留在原处。右侧工作区集中提供预览、图片与提示词、运行详情和底部操作。

- **保存提示词**只保存草稿，不会自动生图或发送。未保存时切换日报、日期或页面，会提醒处理草稿。
- **重新生成**会执行实际生成任务；先确认目标群和日期。请求已接受不代表生成完成。
- **发送**有确认步骤。核对目标群、运行日期、文本与图片，再提交。
- **结果未知**时先去微信核对，不要重复点击发送；使用人工核对入口记录已确认的结果。
- **图片校验失败或诊断图**不能作为正常群报自动交付。先查看失败原因，再修复或重新生成。

## 日期与周报

运行日期与消息覆盖日期并不总相同。日报通常整理前一天；选择“工作日日报 / 周一周报”规则时，周二至周五整理前一天，周一汇总上一自然周，周末不按该规则自动发送。以界面显示的覆盖起止时间为准。

排行榜由程序统计；总消息数与有效消息数取决于群配置。检查统计口径后再比较不同群的数字。

## 找到输出与排错

每份运行资料保存在 `output/<群>/<运行日期>/`，常见文件包括 `ranking.txt`、`ranking.json`、`messages.json`、`image_prompt.txt`、`daily_image.png` 和 `run.json`。失败或禁用图片的任务不一定产生全部文件。

| 现象 | 优先检查 |
| --- | --- |
| 更新后仍是旧界面 | 按升级指南重新构建前端，然后 `Ctrl+F5`；重启脚本不会自动重建已有 dist |
| 微信历史读取失败 | 设置中的 MCP 地址、凭据、WeChatDataAnalysis 状态与实际群绑定 |
| 没有图片 | 该群是否启用图片、模型登录、生图状态与运行任务中的失败原因 |
| 发送失败或未知 | 微信是否登录、桌面是否可交互、目标群与实际聊天记录 |
| 配置与 `.env` 不一致 | 网页保存的配置持久化到数据库，可能覆盖同名环境配置 |

提交问题时只附脱敏后的错误与复现步骤；不要上传数据库、真实聊天、密钥或未脱敏截图。
