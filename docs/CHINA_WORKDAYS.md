# 中国工作日群报

`china_workdays` 使用北京时间。工作日 00:15 生成、10:00 起按群 ID 串行发送；普通周末和国务院公布的休息日不生成、不发送，调休上班日照常运行。统计区间为严格早于执行日的最近工作日零点至昨天 23:59:59，因此普通周一包含周五至周日。多日群报使用 Top10，不生成周报冠军，也不参加独立每周洞察自动任务。

年度数据来自 holiday-cn 的国务院公告结构化副本，附带官方出处；2025、2026 年预置文件用于离线运行及跨年计算。原始数据与项目采用 MIT 许可，来源 https://github.com/NateScarlet/holiday-cn 。运行缓存位于 `data/work_calendar`，启动及每天 00:05 刷新前一年、当年、下一年，未公布年份或联网失败不会覆盖已有有效数据。缺失、损坏或相邻年份冲突时暂停相关自动任务，工作台显示原因，不使用普通周一至周五替代。版本副本保存在缓存的 `versions` 目录。

任务清单和 run.json 保存统计范围、日历版本、临时安排 ID；已生成任务不随日历更新重新计算。历史任务不会被启动恢复自动发送，未知结果、失败发送锁和现有 30 分钟迟发窗口保持有效。

用户确认：仅六个启用群（23–28），统计 9 月 25–27 日，28 日 10:00 开始发送。24 日未发群报保留，不自动补发。临时安排保存在 `data/work_calendar/overrides.json`，按群和执行日期限定，29 日起自动按普通规则运行。

服务停止且确认真实数据库/输出目录后，预览配置：

```powershell
.\.venv\Scripts\python.exe -X utf8 -m scripts.configure_china_workdays --database data/groupbrief.db --calendar-dir data/work_calendar --output-dir output
```

相同命令加 `--apply` 才写入：先进行 SQLite Online Backup、保存日历和调度状态，再事务更新六群规则并创建28日任务清单；重复执行不重建任务。遇到群身份、时间或已有清单冲突时停止。部署继续使用已有 Alter GroupBrief-Backend / 8766，不新增实例。回滚时停止该服务，恢复操作收据目录里的配置/数据库/调度备份及部署前 Git 版本，重新构建前端后启动。

微信发送需要开机且解锁的 Windows 桌面、微信和 WeChatDataAnalysis。配置完成不代表未来已经送达；实际送达应核对每群发送凭据。
